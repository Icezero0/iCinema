# iCinema 桌面端的 B 站播放验证原型

解析时会对每条视频、音频轨道的可用 CDN 候选分别下载一小段数据，优先选择实测更快的候选。加载结果显示选中的主机和预检速度。预检有超时限制；若测速均未完成，则仍使用通过 Range 验证的首个候选。短段测速可能命中已经播放或缓存过的内容，不能代表后续持续下载速度。页面底部现在显示实际播放时最近 8 条视频和音频 Range 请求的状态、接收字节与耗时；请在卡顿发生时记录这里的内容，而不是重新点击“对比测速”（它会卸载并重载播放器）。修改 `main.cjs` 后应完全退出并重新启动原型；不需要新增依赖。

Shaka 的前方缓冲目标原为默认 10 秒。原型现按视频时长设置预取目标，最多 300 秒：短于 5 分钟的视频会尽量一直预取到片尾，长视频保持最多 5 分钟前方目标。目标只是播放器尝试维持的缓冲量，不保证网络、CDN 或浏览器媒体缓冲区一定能填满；实际值请看页面的“前方缓冲”与播放请求诊断。

如果实际播放时某个视频或音频 Range 请求失败，或传输超过 2 秒后未收完便中断，下次请求会尝试切到同一轨道已通过 Range 验证、且文件大小一致的备用 CDN；不会在候选之间反复循环。诊断行会显示“下次改用”的主机。流已经中断的这一次响应无法就地换源，需要播放器发起下一次请求；若所有候选都失败，仍需重新解析或进一步排查。

媒体转发现在还会核对实际接收字节与响应声明的 `Content-Length`；不足时不会再把该 Range 记作“完成”。页面的“缓冲终点”和“播放事件”用于调查暂停在 0 秒时，缓冲条突然清空的情况。

这个目录属于 [`desktop/`](../../README.md) 的一次性技术验证，**不是单独的 B 站桌面应用**。当前原型尚未复用 iCinema 前端或连接后端；它只验证未来 iCinema 桌面客户端能否在本机完成 B 站登录和播放。原型不修改房间数据，也不经过 VPS 转发媒体。B 站登录使用 Electron 的独立持久会话，登录数据只保存在当前电脑的 Electron 用户数据目录，退出应用后仍可复用；点击“退出 B 站登录”会清除该会话。原型不读取 Chrome 的 Cookie，也不将 B 站 Cookie、playurl 或 CDN 地址写入仓库、日志或 iCinema 服务。持久登录意味着同一台电脑的其他系统用户若能访问你的用户数据目录，也可能接触该会话，请仅在可信设备上使用。

需要用户审核并自行安装的两个依赖：Electron `44.7.0`（桌面容器）和 Shaka Player `5.2.12`（普通 DASH 播放）。在项目根目录的 PowerShell 中运行：

```powershell
npm install --prefix .\desktop\probes\bilibili --no-audit --no-fund
```

安装后运行：

```powershell
npm --prefix .\desktop\probes\bilibili test
npm --prefix .\desktop\probes\bilibili start
```

首次运行时，在弹出的 B 站窗口登录；确认登录状态后窗口会自动关闭。下次重启原型时会自动检查本机保存的登录状态，通常不需要再次登录；如 B 站会话过期，则重新登录。切换到本持久会话的首次运行需要重新登录一次，之前内存会话中的 Cookie 不会迁移。示例 BV `BV1JneT6rEaG` 已填入。加载完成后按播放键，并试暂停、拖动及 1.5 倍速。原型只选择普通 AVC 视频和 AAC 音频轨；不处理 DRM、番剧、会员专属或 CDN 地址续期。登录网页或 API 若返回风控错误，应原样记录状态码，不把它当成播放成功。

开发期间若只修改了原型的渲染脚本，可以在原型主窗口按 `Ctrl+R` 重新加载页面；退出应用后再次打开会复用本机保存的 B 站会话。

成功标准：本机会话被识别为已登录；取得该用户有权限的 playurl；本地 Electron 自定义媒体协议能够完成 DASH 视频和音频加载；画面和声音能播放，且 `<video>` 的暂停、跳转和倍速有效。仅有 API 200 或 2 字节 Range 206 不算完成验证。

若播放卡顿，可在原型中选择 720P 或 480P 比较。画质选择是本次验证的固定上限，尚未实现自动降档；播放器下方显示前方缓冲、等待事件、累计缓冲和估计带宽。改动 `main.cjs` 或 `preload.cjs` 后必须完全退出并重新运行原型；登录状态仍保存在本机。

“对比测速”在尚未播放的位置对当前视频最多四个候选 CDN 分别取 512 KiB，保留每个候选的速度或网络错误。当前候选直连成功时，再用相邻的等长分段测试本机自定义协议。测速会暂时卸载播放器并在结束后重新加载，建议在开始播放前使用。结果只显示 CDN 主机名和速度，不输出签名媒体 URL，也不经过 VPS。单次测速会受连接预热与 CDN 波动影响，仅用于定位大幅度的差异。
当前候选的无缓存请求失败时，原型还会用另一段未播放内容按普通缓存策略重试一次，用来排除测速时的 `no-store` 设置本身造成的异常。

解析结果现在还会列出同一视频不同画质和编码轨道的候选 CDN 主机名，并标出当前轨道及受限主机；不会列出媒体路径或签名参数。允许列表包括 `*.bilivideo.com` 和 B 站命名形式的 `upos-*.akamaized.net`，其他主机仍不会被原型请求。

使用新实现的固定域名 HTTPS 客户端与解析器，对作品 `2019219963`《鬼灭之刃》完整读取详情及26集线路接口。26集全部成功；首集去重后12条，其余每集11条，均为支持的 M3U8 地址，无跳过项。未请求媒体清单/分片、未启动服务、未写入用户业务数据库。缓存、失败保护、权限及并发通过隔离数据库测试验证；房间播放留待后续阶段。以下保留前一次样本报告。

核验日期：2026-09-18。样本：[用户指定的第1集播放页](https://omofun.in/vod/play/2026723920/ep1.html)。使用项目venv和标准库读取公开页面、页面自身调用的JSON；没有启动服务、修改业务代码、导入数据库或下载视频。

## 结论摘要（300字以内）

可行：样本《咒术回战 第三季》的详情及播放页公开列出12集，播放脚本调用/_dyn_plays/{作品ID}/{集标识}获取JSON，video_plays逐条给出src_site与play_data（M3U8）。实测第1集16条、第2及12集各15条，无需登录、Cookie或验证码。第1集只有14个来源标识、15个不同地址，存在重复来源及重复链接，导入需去重且允许同来源多线路。这是网站内部接口，未确认全站增量、稳定性或链接长期有效性；按“取得M3U8即可”的验收标准通过。

## 页面如何取得线路

播放页内联脚本使用GET请求：

```text
https://omofun.in/_dyn_plays/2026723920/ep1
```

返回HTTP 200，Content-Type为application/json。顶层包含video_plays和html_content。以下为实际响应中第一条线路的节选，其余字段与线路省略：

```json
{
  "video_plays": [
    {
      "play_data": "https://vv.jisuzyv.com/play/bW66X9na/index.m3u8",
      "src_site": "jszy"
    }
  ]
}
```

页面将play_data直接交给DPlayer的HLS播放模式，切线时更换该地址。页面按钮名称取src_site前两个字符并转大写，例如JS线路。提取链接只需解析JSON，无需运行页面广告脚本或使用无头浏览器；html_content不是取得地址的必要字段，不应直接渲染到本站。

## 实测范围

| 请求 | 结果 |
| --- | --- |
| `/vod/play/2026723920/ep1.html` | HTTP 200；包含动态请求路径、切线脚本及ep1至ep12链接 |
| `/vod/detail/2026723920.html` | 正常返回《咒术回战 第三季》详情及12个不同剧集链接 |
| `/_dyn_plays/2026723920/ep1` | 16条线路，16条地址的路径均以.m3u8结尾 |
| `/_dyn_plays/2026723920/ep2` | 15条线路，15条均为.m3u8地址 |
| `/_dyn_plays/2026723920/ep12` | 15条线路，15条均为.m3u8地址 |
| 再次请求ep1 | 仍为16条，14个不同src_site，15个不同URL |

仅带普通User-Agent请求，未提供Referer、Cookie、账号或验证码。请求串行，样本之间约1.3秒间隔。该间隔是本次测试选择，不代表已获知网站官方限流规则。未检查M3U8清单或媒体分片，也未验证浏览器播放；这些不影响用户定义的“取得资源链接”结论。

第1集来源顺序为：jszy、gszy、hnzy、mdzy、ikzy、bfzy、hnzy、ffzy、lzzy、ffzy、ukzy、xlzy、wjzy2、snzy、jyzy、yhzy。第12集的来源顺序不同，因此不能按数组下标作为跨集固定线路身份。

重复情况：hnzy两条的完整URL相同；ffzy两条的域名与路径不同。故“返回16条”不等于16个独立资源站，也不能只按src_site去重，否则会丢弃不同地址。

## 对iCinema的意义

可以把Omofun作为一个聚合数据来源：读取详情页实际剧集链接，再逐集请求动态接口，整理为“作品→剧集→线路→HLS链接”。它与当前MacCMS列表/详情协议不同，需要单独适配器，不能只把域名填入现有采集站地址就直接使用。

数据来源应记录为Omofun，并单独保存src_site作为它返回的线路来源标记。这个标记不能直接证明资源站真实身份，也不能未经映射当作本地采集站ID。推荐同一集内相同来源、相同URL去重；同来源的不同URL保留为不同候选线路。短时间样本不足以确定这些候选能否跨集稳定对应，正式接入前需设计与验证线路身份。

现有数据库的唯一约束是“同一集+同一线路”，接入时必须给同来源多地址分配不同线路身份，不能覆盖旧播放项。UI线路数量以每集实际可用候选为准，不固定数量。

## 尚未验证

- 其他作品、特殊篇或非标准集号的完整覆盖。
- 是否有公开全站目录、更新时间增量接口，以及站点更新时延。
- 内部接口兼容承诺、长期限流、地址变更及过期规则。
- 每个来源条目的内容是否正确、重复来源为何出现，及与直接采集站结果的可靠对应。

因此，结论是“样本链接获取可行”，不是已完成全站稳定采集器。当前无需新库或包；若后续接入，先实现独立适配和小批量去重测试。

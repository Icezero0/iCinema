## 原因

`backend/app/modules/catalog/import_parser.py` 的 `episode_identity` 使用 `re.fullmatch`，普通集名只接受“第数字集/话”“EP数字”或纯数字。因此“第1集”“第50集”可识别，加上“完结”“已完结”便不再匹配。

`parse_detail` 先判断集名；失败即记录 `unmapped_episode: 原始集名` 并跳过该条目，尚未进入 URL 校验。这就是“集名无法可靠识别，未建立映射”的实际触发路径。

电影仅有一个条目，被跳过后 `entries=[]`；聚合预览计算得到0个可导入来源，于是展示“未解析到可导入的 HLS 播放项”。它是前一个解析失败的后果，不代表接口没有返回 HLS 地址。

ZZZ的两版均保留第1–49集，仅第50集被跳过；单凭这次接口数据，不能重现ZZZ整部资源“无HLS播放项”的结果。如某个旧任务这样显示，需要进一步比较该任务的来源配置及当时快照。

日语版上游标题在ZZZ之后另含零宽空格 `U+200B`。这不是本次集名报错的原因，但按完整标题检索和比对时也需要注意。

## 建议

集名标准化可明确支持末尾“完结”“已完结”等状态标记，保留原始集名，再识别集号；不能直接允许任意后缀或提取任意数字，否则合并集、上下篇等仍可能错配。应补充这三项真实数据的回归用例，并继续拒绝含糊集名。本次按请求输出诊断，尚未更改解析规则。

# 金鹰增量采集可行性报告

核验日期：2026-09-18。仅请求公开采集接口，未修改采集业务或导入数据库。以下数量为当时实测值，不代表固定规模。

## 结论摘要（300字以内）

金鹰支持按分类及最近若干小时增量获取作品，支持分页详情、批量ID和调整每页数量。日本动画全量2486部/125页；最近24小时9部/1页，详情接口一次取得9部播放信息；最近7天84部，50条/页时仅2页。建议首次全量建立来源目录，之后定时增量同步，本站检索使用本地目录。按每站上次成功覆盖时间计算窗口，保留重叠，失败不推进进度；已导入作品补集补线路，新作品由管理员选择建档。需定期全量核对，不将分页位置作为长期同步进度。

## 请求与实测

接口：`https://jyzyapi.com/provide/vod/from/jinyingm3u8/at/json`

| 参数 | 结果 |
| --- | --- |
| `ac=list&t=25&pg=1` | code=1，total=2486，pagecount=125，limit=20 |
| `ac=list&t=25&h=24&pg=1` | total=9，pagecount=1 |
| `ac=list&t=25&h=168&pg=1` | total=84，pagecount=5 |
| `ac=list&t=25&h=168&pg=2` | 返回20条，时间由2026-09-16 20:28:02到2026-09-14 18:42:03，按更新时间倒序 |
| `ac=detail&t=25&h=24&pg=1` | 返回9部详情，9部均包含m3u8地址 |
| `ac=detail&ids=115075,87022` | 返回指定2部详情，均包含m3u8地址 |
| `ac=list&t=25&h=168&pg=1&pagesize=50` | limit=50，返回50条，pagecount=2 |

请求以约1.3秒间隔串行发出，不下载视频。此前请求曾返回403；本次以上请求均返回可解析的成功JSON，不能把单次403认定为接口不支持相关参数。

## 排序与能力边界

本次抽样符合vod_time倒序；苹果CMS官方实现默认按vod_time倒序，但不保证金鹰所有版本或同时间记录的稳定顺序。分页期间上游更新会改变记录位置。`h`是相对上游当前时间的小时窗口，并非固定起止时间快照。

金鹰帮助页明确说明关闭后台搜索，所以不能依赖`wd`。本次未重新请求关键词搜索，也未实测自定义排序、任意起止日期或删除通知。`pagesize=50`已验证，不能据此推断其他任意值。

## 建议设计

1. 每个采集站、分类及配置版本独立维护来源目录和同步进度；首次全量同步。
2. 每天固定时间执行增量，按上次成功覆盖时间至本次开始时间计算小时数并加重叠窗口，例如每日采集最近26小时。停机后自动扩大补采范围。
3. 优先分页获取详情；大响应或需要筛选时使用目录及批量ID详情。相同来源ID幂等更新，不覆盖管理员保留字段。
4. 完整处理成功才将进度推进至本次开始时间；失败重试，不丢弃之前进度。统一时区，对上游缓存、时钟误差及动态分页做重复检查与周期性全量核对。
5. 来源同步和本站建档分离：新作品进入本地候选目录，已有作品自动补充剧集及线路；管理员保留立即同步、筛选及选择导入入口。

这是已验证能力与后续设计建议，尚未实现定时同步或目录缓存，无新增依赖。

# CMS 管理后台：重新打开与工作交接

记录日期：2026-09-22。用户在本机执行 PowerShell 命令，在自己的 SSH 窗口执行 VPS 命令；开发者不代连 VPS。此文与[分阶段计划](../architecture/cms-implementation-stages.md)、[C1报告](../reports/cms-external-stage-01.md)配套。

## 1. 下次开机如何打开后台

CMS 安装在 VPS 上。本机重新开机后，通常只需重新建立 SSH 隧道并打开浏览器，不需要重新安装或重启服务。

在**本机 Windows PowerShell**执行，下方连接目标须替换为原来使用的实际地址：

```powershell
ssh -N -L 127.0.0.1:18080:127.0.0.1:18080 -o ExitOnForwardFailure=yes ubuntu@你的VPS公网IP或域名
```

- 如果平时使用 SSH 配置别名，可以用该别名替换整个 `ubuntu@你的VPS公网IP或域名`。
- 原 SSH 连接如需 `-p` 指定端口、`-i` 指定密钥，仍沿用那些参数。
- 完成认证后没有输出、没有返回命令提示符是正常的；保持这个 PowerShell 窗口打开。
- 会话里没有提供实际公网 SSH 地址，不能将终端主机名 `10-7-58-104` 当作公网连接地址。

然后用浏览器打开：

```text
http://127.0.0.1:18080/已改名的管理入口.php
```

实际入口及可直接打开浏览器的 PowerShell 命令保存在本机 [访问记录](../../data/local-notes/cms-admin-access.md)。`data/` 已被 Git 忽略，该记录不会随项目提交；其中没有密码或私钥。

如本地访问记录丢失，在**普通 VPS SSH 窗口**执行以下只读命令，取得后台地址：

```bash
find /var/www/icinemacms -maxdepth 1 -type f \
  -name 'manage_*.php' -printf 'http://127.0.0.1:18080/%f\n'
```

## 2. 打不开时检查什么

只有访问异常时，才需要在**VPS SSH 窗口**执行：

```bash
systemctl is-active nginx php8.3-fpm mariadb
sudo ss -lntp 'sport = :18080'
```

预期三个服务均为 `active`，CMS 监听 `127.0.0.1:18080`。正常时不必执行 restart、reload 或修改 Nginx 配置。隧道命令如提示本机端口被占用，先检查是否已有一个隧道窗口正在运行。

## 3. 本机关机的影响

- 本机关机后 SSH 隧道和浏览器关闭；VPS 上的 CMS 服务及数据库继续保留。
- 手动“采集所有”依赖浏览器逐页跳转，关闭页面后后续分页不会继续；已经写入的数据保留，当前服务器请求可能仍会完成。
- VPS 定时触发尚未配置验证，不能视为已实现无人值守采集。下次开机也不会自动接续手动采集。

## 5. 下次从哪里继续

1. 建立隧道、登录后台，打开“采集 → 自定义接口”。
2. 从出现错误的站点那一行点击站名/接口地址，查看资源列表上方的分类绑定情况；`[绑定]` 表示未绑定，红色本地分类名表示已绑定。缺少本地分类时到“基础 → 分类管理”新增，再回到当前站绑定。
3. 绑定依赖完整接口 URL 和上游分类 ID。换域名、路径或末尾斜杠可能形成另一组绑定，必须核对当前采集使用的那条接口。
4. 先勾选少量作品“采选中”，到“视频 → 视频数据”确认资料、剧集和播放地址；重复采集并从第二站采同一作品，验证去重及线路追加规则。
5. 小样本通过后再逐站全量。不要并行启动五站手动采集，当前视频断点记录共用；重新点“采集所有”从第一页开始，不能假定自动续跑。
6. 再配置服务器定时触发、增量范围和漏跑补采，最后推进 iCinema 对接。每天几点执行与采集最近多少小时是两项设置；CMS 记录的运行时间不是完整成功水位。

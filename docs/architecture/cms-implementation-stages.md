### O2 当前本地验收

进入自己的房间，打开播放器控制栏的播放源面板，选择 Omofun。独立 `/omofun` 页面及路由已移除，不新增侧栏入口。

1. 面板包含链接/作品ID输入、当前解析状态与成功作品名、解析进度和“打开选集”。输入作品与房间已成功解析作品相同时，按钮显示“重新解析”并强制重取（保留冷却限制）；不同时显示“解析”并优先复用24小时内成功缓存。粘贴同作品链接与直接输入ID等效，回车与点击行为一致，不再单设刷新按钮。Omofun标签使用独立影片图标。
2. 在居中遮罩弹窗中选择数字集号，再点击线路按钮，将该线路应用到房间并关闭弹窗。页面不显示或复制外链；按钮按Omofun来源前两位大写加“线路”，保留新解析结果的上游顺序，完全重复地址去重。
3. 使用第二个房间成员检查选集切线同步；无主动同步权限的成员不能应用线路。切集或换线后暂停、进度从0开始。
4. 播放中点“重新解析”：只有数据更新，没有切源广播、播放器重载或进度重置；随后加入的成员仍使用房间当前播放快照。再次明确选择线路才采用新的地址。
5. 关闭弹窗、点击遮罩、Esc、窄屏及全屏下检查布局与交互，核对中英文和主题。回到外链模式时输入框不能暴露刚才的Omofun地址。
6. 成功解析A后输入B但不点解析，“打开选集”仍显示A。即使没有选择播放线路，退出重进也恢复A及成功状态。弹窗使用不透明的共通卡片背景。运行时丢失后当前播放仍从独立持久快照恢复为暂停，不自动采用最新缓存。

底层复用外链/HLS媒体引擎，房间语义仍为Omofun。63项后端相关回归（含新增8项房间测试和迁移检查）、9项前端测试、类型检查及生产构建通过。公网单条线路能否播放依赖上游，完整多人浏览器验收由用户运行的本地服务完成。本阶段报告见[O2报告](../reports/omofun-stage-02.md)，[O1报告](../reports/omofun-stage-01.md)保留历史记录。

O2新增迁移 `b38fa2fb9723`，在 `room_settings.omofun_source` 保存当前播放地址及作品/剧集/线路/缓存版本，独立于共享缓存。无需安装依赖，若热重载未自动应用迁移，在 `backend` 执行 `.\venv\Scripts\python.exe -m alembic upgrade head`。开发者未启动服务、未手动迁移用户业务数据库。

本次面板修订新增迁移 `c49ab30ca834`：`room_settings.omofun_resolution` 单独保存解析对象及状态。房间接口 `GET /api/v1/omofun/rooms/{room_id}` 恢复状态，`POST /api/v1/omofun/rooms/{room_id}/resolve` 提交解析；读取要求房间成员身份，解析要求主动同步权限。客户端在Omofun面板激活时轮询，离开后任务仍可完成，重进读取时结算状态。输入草稿不写入房间。修订验证40项后端测试（含迁移）、9项前端测试、类型检查及构建通过；见[修订报告](../reports/omofun-room-panel-update.md)。

### O1 运行边界

独立 `omofun_cache` 表保存成功快照和解析任务；无新增依赖。新增迁移 `a27e91ea8612`，通常由现有后端热重载后的启动流程应用；若未应用，在 `backend` 目录运行 `.\venv\Scripts\python.exe -m alembic upgrade head`。开发者未启动服务或手动迁移用户数据库。

请求固定访问 Omofun 公网 HTTPS，不跟随重定向、不执行网页脚本、不请求视频数据。全局最多2个解析任务，每用户最多1个；跨作品新任务间隔至少10秒，站点请求间隔至少1.3秒。每部最多500集、每集最多128条原始线路、单次响应2MiB、成功快照8MiB、任务20分钟。超限或某集无法解析不发布部分缓存。

任务使用应用进程后台执行和90秒心跳租约；服务中断后旧成功缓存仍在，租约到期显示中断，可重新解析；本阶段不实现独立常驻队列或自动断点续跑。当前接口为已登录用户可用的 `POST /api/v1/omofun/resolve` 与 `GET /api/v1/omofun/{work_id}`，响应禁止浏览器缓存，返回不含任务令牌和请求者信息。

## 协作与验收约定

- 用户提前运行前后端，开发者不启动、重启或停止服务；修改保存后由现有服务热更新。
- 每阶段提交 `docs/reports/cms-stage-NN.md`，正文不超过300字，说明问题/目标、交付、检查、验收入口及必要限制。
- 完成阶段后告知用户重点页面与功能，用户在自己的本地服务验收，通过后再推进下一阶段。
- 后端由开发者完成适当的单元/API测试，使用隔离测试数据库，不要求用户手动测试后端。
- 采用共通组件、主题与中英文 i18n；弹窗居中带遮罩、反馈使用 toast，不添加开发提示和多余副标题。
- 需要引入包、服务或第三方文件时，先说明用途与安装命令；后端始终使用当前项目 venv。
- 数据迁移沿用项目方式。需用户操作时给出明确命令，不把热重载等同于已经完成迁移。

## 阶段1–3：当前成果与验收基线

历史报告见[阶段1](../reports/cms-stage-01.md)、[阶段2](../reports/cms-stage-02.md)、[阶段3](../reports/cms-stage-03.md)。历史报告记录当时交付；当前交互以本节为准，不再使用旧的“选站点和页数导入”或逐集手填作为主流程。

### 当前页面

- `/admin/videos`：统一管理入口。分类目前只有“日本动画”，并非代码限定只能存在该分类。新增/编辑居中弹窗，年份使用项目控件；保存 toast；支持确认删除。
- `/admin/videos/:id`：仅剧集主卡片，集号为数字按钮网格；选中后展开线路按钮，点击复制地址。优先显示采集站缩写，未填则名称；不显示播放 URL 或追加 M3U8。
- `/admin/providers`：采集站实例配置、缩写、分类映射、播放组及连接检查；金鹰是预置实例。保存反馈为 toast。
- `/admin/imports`：标题“资源导入”，按名称、分类及更新日期在已启用站点检索；任务详情为遮罩弹窗。结果以共通列表展示，选择由样式区分，无 checkbox 和额外选中打钩。来源站数、集数及新增集数位于第二行。
- 资源采集站、资源导入从视频资源管理页面进入，不恢复侧栏独立入口；返回也回视频资源管理。

检索进行中和手动中断后，已取得且可导入的结果仍能选择；导入不自动终止剩余检索。已有作品可补集或补充新站线路；重复导入不重复建档。缺集不伪造线路，季名保留在作品名称中。

当前解析先提取 M3U8 地址再识别集号；无集号按顺序兜底，插入集支持 x.5/x.51 等规则。该规则不保证所有特殊篇都能跨站正确对应，后续需人工映射入口。

### 当前限制

当前跨站检索仍需分页获取上游目录及详情，尚无跨任务来源目录缓存、定时增量水位和可靠自动续跑。后台任务在应用进程中执行，任务数据持久化不等于进程重启后自动恢复执行。金鹰名称搜索不能依赖上游 `wd`；这是阶段4要解决的主要效率问题。

目前仅金鹰完成实际采集站接入验证，其他实例的模拟测试不代表所有站点实际兼容。完整人工合并/拆分、显式字段锁定、用户目录、房间catalog模式尚未交付。管理页点击线路仍仅复制地址；独立Omofun路径已按O2接入房间。

## 阶段4：来源目录与定时增量同步

### 交付

1. 独立来源目录，保存未导入候选及详情；按站点、分类和配置版本记录覆盖范围与水位。
2. 首次分类全量同步，之后可配置每日时间与时区；使用金鹰已验证的 `t/h/pg/pagesize` 与详情分页/批量详情能力。
3. 按距上次成功水位的实际时长加重叠窗口补采；仅完整成功推进到任务开始时间。失败、取消和超限不推进；增加周期完整对账。
4. 持久任务、租约、游标、分批提交、取消及恢复；复用既有 jobs 方式，避免直接扩大当前任务上限。
5. 资源导入改为检索本地来源目录；已有作品自动补充更新，新候选供管理员选择建草稿，均不自动发布或覆盖人工状态。

### 本地验收重点

- 资源采集站：首次同步、覆盖进度、最后成功时间、计划时间及手动同步。
- 资源导入：名称/分类/更新日期筛选响应、跨站聚合、已建档作品补线；不再每次检索都重新全量抓取。
- 任务详情：取消后保留成果、失败重试、覆盖不完整提示；新候选不自动成为已发布资源。

后端重点测水位推进、漏跑补采、重叠去重、断点恢复、配置变化、人工值保护、站点隔离及新集更新。无需为测试等待一天，应使用可控时钟和任务触发入口。

## 阶段5：Omofun 解析服务与持久缓存

### 交付

1. 规范化作品 ID 和允许的网址，在后端按固定模板读取详情及每集线路。
2. 现有数据库中增加独立缓存表，不写入正式作品库；保存完整成功快照、版本、最后成功时间与刷新任务。
3. 缓存不足24小时直接返回；首次、过期或主动刷新启动解析；同作品并发合并，有限重试与限频。
4. 分批取得数据但完整成功才原子替换；失败保留旧快照和成功时间，不将部分失败伪装为成功。
5. 提供最小输入、进度、选集及线路预览入口，为阶段6房间面板复用。验收入口路径在实施报告中给出，不新增无必要侧栏。

### 本地验收重点

- 输入 ID 与完整网址应指向同一作品；首次解析可看到进度和剧集线路。
- 同一作品再次请求命中缓存；主动刷新期间旧数据仍在，失败后仍保留。
- 同来源多地址不会丢失，完全相同地址去重；不同剧集线路数动态变化。
- 非允许网址拒绝；不会自动在视频资源管理中新增该作品。

后端重点测24小时边界、失败不续期、并发刷新合并、解析不完整、稳定标识、任务超时及地址校验。过期由测试时钟验证，不要求用户实际等待24小时。该阶段暂不改变房间播放。

## 阶段6：四模式房间播放

### 交付

1. 视频链接、本地视频、资源库、Omofun 四模式，持久化选择，保留原有两模式行为。
2. 用户搜索已发布资源库；Omofun 输入作品并使用阶段5缓存；统一选集与线路交互。
3. 服务端房间播放快照与递增源版本，成员权限检查和迟到异步结果丢弃。
4. 缓存刷新只更新候选，不重载播放器；资源库后台同步同样不影响当前播放。新加入成员使用房间已选快照。
5. 显式切集、换线或重新加载才采用新数据；重启恢复为暂停，不承诺续播进度。

### 本地验收重点

- 用两个浏览器加入同一房间，检查四模式切换、选集、选线及权限。
- A 正在播放时刷新缓存得到 B，确认两端无暂停/重载/进度归零；刷新后新加入的第三端仍得到房间快照 A。
- 明确重新加载或选新线路后，全房间才统一使用 B；缓存删掉旧线路也不自动替换当前线路。
- 快速切换作品/模式，旧解析结果不能覆盖新选择；刷新按钮与重新加载作用分明。
- 视频链接和本地视频原功能回归，禁用资源按明确策略通知处理。

后端测试权限、快照版本、模式持久化、重连及竞态；前端检查状态和播放器副作用。多人同步使用可控 HLS 样本验收，第三方地址可获取不代表分片必能播放，不以某条公网线路失效否定采集功能。

# iCinema 现有业务 Electron 化计划

日期：2026-10-09。开发分支：`feat/electron-desktop`。本计划先让现有 iCinema 业务成为可用的桌面客户端；B 站账号、解析和播放功能在此基础稳定后另行接入。`desktop/probes/bilibili` 仅作为后续技术验证资料，第一阶段的正式应用不调用它。

## 边界与结构

- `frontend/` 继续维护唯一的 Vue/Vite 界面及房间逻辑，避免复制一套桌面页面。
- `backend/` 继续提供现有账号、房间、聊天与同步服务；本阶段不在桌面端内嵌 Python 服务，也不修改房间播放源模型。
- `desktop/` 负责 Electron 主进程、窗口与将来确有必要的本机能力。首版网页窗口关闭 Node 集成、开启上下文隔离与沙箱，不向普通网页暴露原型里的 B 站 API 或媒体协议。
- 开发时加载已运行的 Vite 页面，以便现有热更新继续有效；发行版将加载前端构建产物，并明确配置后端地址。不能仅把生产网站地址放进一个空壳就算完成桌面化。

## 推进与验收

1. **开发版桌面壳。** 用 Electron 打开现有前端，不改业务页面；限制窗口导航，外部 HTTP(S) 链接交给系统浏览器。验收登录/退出、主页房间列表、进入房间、聊天、房间设置、现有外链/本地文件/Omofun 播放，以及关窗重开后的登录状态。用户继续自行启动前后端服务；修改保存后由 Vite 热更新。此阶段不出现 B 站入口。
2. **独立发行版。** 让桌面端从打包的前端静态资源启动，处理 Vue History 深链接与刷新、API/WebSocket 地址、图片资源、会话持久化、外部链接、本地文件能力及窗口重启。验收无需启动 Vite 即能登录并完成上述核心业务；后端仍为现有服务。
3. **回归与交付。** 对桌面端和网页端同时检查播放控制、实时同步、权限与常用页面；构建可运行的 Windows 应用。每一阶段结束提交不超过 300 字的简报，并列出应由用户打开的页面与操作。

## 安装与运行约定

不主动启动用户的前后端服务。若新增或迁移依赖，先给出用途、版本和本地安装命令，由用户审阅后自行安装；后端需要命令时使用项目内的 `backend/venv`。桌面壳验收由用户在本机运行，我不会轮询等待用户操作。

B 站功能的后续设计见 [Bilibili 播放接入计划](bilibili-provider-plan.md)。它以本计划完成的桌面客户端为前提，不在现有业务 Electron 化期间混入。

# iCinema 资源库、Omofun 与房间选片设计

日期：2026-09-19，修订版 v5.2。本文统一替代此前总体计划；阶段进度与验收见[分阶段实施与本地验收](cms-implementation-stages.md)。资源库方向暂停，优先按 Omofun O1/O2/O3 推进。O1解析缓存已实现；O2房间播放源面板及选集弹窗已实现，待用户验收。

## 1. 目标与已确认决策

同时建设两条资源获取路径：

| 路径 | 数据从哪里来 | 何时获取 | 用户如何使用 |
| --- | --- | --- | --- |
| 资源库 | 管理员配置的多个资源采集站 | 首次同步，之后定时增量更新 | 在本站搜索作品、选择剧集和线路 |
| Omofun | 用户提供的 Omofun 作品 ID 或网址 | 首次解析、缓存超过24小时或用户主动刷新 | 输入作品，选择解析出的剧集和线路 |

两条路径共用房间选集、选线与同步播放能力，但不混用作品管理流程。Omofun 解析结果保存到独立缓存表，不自动成为资源库作品，也不要求管理员逐部建档。

房间提供“视频链接”“本地视频”“资源库”“Omofun”四种模式。**缓存刷新和后台同步都不得自动打断正在播放的房间。** 新数据供下一次明确选集、换线或重新加载使用。

当前分类仅预置“日本动画”，分类模型保持可扩展；金鹰是首个采集站实例，不是写死的唯一来源。线路数量由每集实际聚合结果决定。暂不建设未来正版资源站协议、权益体系、DRM、全站 Omofun 爬虫或自动换线。

现有技术基础为 FastAPI、SQLAlchemy、Alembic、SQLite，以及 Vue 3、TypeScript、Pinia、Vite、i18n 和共通组件。房间运行时状态仍在进程内；新增任务不能据此假设已经支持多 Web worker。

| 能力 | 当前状态 |

| 管理员作品管理 | 已有分类、编辑、发布状态、禁用、删除、版本冲突与操作记录 |

| 资源采集站 | 已有可配置实例、连接检查、分类映射、播放组和可选缩写 |
| 检索与导入 | 已有多实例检索、保守聚合、预览选择、幂等更新、取消和重试；检索过程中及手动中断后可导入已取得结果 |
| 目录缓存及定时增量 | 尚未实现；当前检索仍需扫描上游目录并筛选 |

| Omofun | 后端解析及独立持久缓存已接入房间播放源面板，独立预览页已移除 |
| 房间资源模式 | 当前支持视频链接、本地视频及Omofun；资源库暂缓 |

验证依据：

- [金鹰接入评估](jinying-provider-assessment.md)与[增量参数评估](../reports/jinying-incremental-assessment.md)：已取得作品、剧集及 M3U8；后续验证了分类、相对更新时间窗口、分页、批量详情和分页详情。
- [Omofun 验证](../reports/omofun-link-feasibility.md)：公开详情页提供选集，页面调用的 JSON 提供每集线路。属于网站内部接口，不等于稳定的采集协议。
- 取得 M3U8 地址即满足采集可用性要求；不把单线路播放失败视为导入失败。真正的多人播放另用可控视频验收。

## 3. 资源库路径：先同步，再检索与导入

目标流程：

采集站配置 → 同步来源目录与详情 → 管理员本地筛选、预览 → 选择导入或更新 → 发布作品 → 房间使用。

### 3.1 将来源目录与正式作品分开

新增独立来源目录记录，以“采集站实例 + 上游作品 ID”唯一标识，保存名称、分类、更新时间、规范化详情、原始必要字段、详情获取时间及同步批次。未导入的条目也保留，避免每次检索重复抓取。

管理员依旧按名称、分类、更新日期筛选所有符合条件的已启用采集站，不要求先选择某一个站。每项显示来源站数、集数、预计新增集数和已建档状态；聚合不确定时保留独立候选与必要警告。目录尚未完整同步时必须标明覆盖状态。

已有作品可以再次导入，用于补充新集、更新地址或增加新站线路。新作品默认草稿，不自动发布；定时同步可以更新已绑定作品的剧集与线路，但必须保护人工修改、映射及禁用状态。

第一轮同步可先取得列表，再分批取得详情。没有详情的条目不能宣称已知完整线路数量；统计完成后才作为完整预览。批量导入应明确作用于当前选择或全部筛选结果。

### 3.2 金鹰参数与增量策略

已验证可用参数包括：

| 参数 | 用途 |
| --- | --- |
| `ac=list` / `ac=detail` | 列表 / 含播放数据的详情 |
| `t` | 上游分类 ID，由配置映射本地分类 |
| `pg`、`pagesize` | 分页；页大小按站能力和响应大小上限设置 |
| `h` | 最近若干小时内更新的条目 |
| `ids` | 按作品 ID 批量取得详情 |

金鹰帮助页说明搜索关闭，不能依赖 `wd` 实现名称查询。名称筛选改在本站来源目录进行；绝对日期范围由本站过滤，增量请求使用上游支持的相对小时窗口。其他站是否支持这些参数，须逐实例验证。

首次按配置分类完成全量同步，之后每天在可配置时间运行增量任务，明确调度时区。每个“采集站 + 分类映射 + 配置版本”保存独立水位：

1. 记录本次任务开始时间，根据上次成功水位到当前时间计算 `h`，增加重叠窗口并向上取整。
2. 分页取得更新记录；优先使用已验证的详情分页或受响应大小约束的批量详情，减少逐部请求。
3. 分批幂等写入目录，更新已绑定作品，保留新增未导入候选。
4. 只有完整成功后才把水位推进到本次任务开始时间；失败、取消、超限或缺页均不推进。
5. 停机后按实际遗漏时间补采；新增采集站或改变分类配置执行对应基线同步。
6. 周期性完整对账补偿回填旧时间、分页变动等增量遗漏；上游缺项不直接删除或下架本站内容。

实测列表按更新时间倒序，但没有稳定快照或同时间排序保证。重叠、去重和对账均有必要。“每天运行”不等于每次固定请求最近24小时；停机数天也不能只补一天。

### 3.3 调度与可靠性

复用现有 jobs 运行方式评估独立同步执行器，新增持久任务、游标、执行租约和条目结果；当前进程内检索任务不能直接当作可靠定时系统。

每站限速、有限并发和退避，网络请求不占数据库长事务。取消保留已提交结果；恢复从安全检查点继续，并允许重复处理。详情解析失败保留最后成功数据与错误，不能用空结果覆盖完整记录。管理端显示同步覆盖范围、最后成功时间和任务进度。

首版不默认引入 Redis、Celery 或第二套数据库；确需依赖时先说明用途和安装命令。

## 4. 作品、剧集与线路模型

现有核心关系保留：

- `CatalogContent`：本站作品，含分类、名称、年份、地区、形式、发布和禁用状态。
- `CatalogEpisode`：作品内所有来源集号的合集，结合篇目类型区分；不是每个采集站各建一套集数。
- `CatalogLine`：作品下来源实例及播放组对应的线路。
- `CatalogPlayback`：某集、某线路对应的具体地址；没有该集的来源不生成空播放项。
- `CatalogProvider`：资源采集站实例；展示优先缩写，未填则用名称，不自动追加 M3U8。
- `CatalogSource`：已导入的来源作品与本站作品绑定及导入快照。
- `CatalogImportJob`：现有检索和导入任务，不能替代独立来源目录或增量水位。

新增来源目录、同步水位及任务表的具体名称在实现阶段确定。来源目录允许未绑定作品，既有来源绑定要兼容迁移，不能创建两套相互矛盾的归属关系。

剧集解析先提取有效 HTTP(S) M3U8 地址并保留查询参数，再识别集号；无集号按既定顺序规则兜底。明确集号之间的插入项使用 x.5，多项使用 x.51、x.52 等既有规则，并保存原始标签和顺序。该规则是映射策略，不能证明不同站的总集篇内容一致；冲突须可人工纠正。作品名称中的不同季保留，不新增季字段。

自动聚合沿用完整名称、分类及无冲突的年份、地区、形式等保守条件。暂不把固定评分阈值或模糊名称识别当作已实现功能。已有来源绑定优先复用，重要元数据冲突进入待处理，不静默改绑。

完整人工整理后续提供合并预览、主作品选择、剧集对应、拆分、禁止再次合并及字段锁定。自动同步不覆盖这些决定；操作检查版本并记录审计。合并不能仅依据数组下标对齐不同来源的剧集。

## 5. Omofun 路径：按作品解析与持久缓存

### 5.1 输入与解析

用户输入作品 ID 或已支持的 Omofun 网址。后端提取并规范化作品 ID，再根据固定域名和路径模板访问详情页及每集线路接口；不能直接抓取用户提供的任意 URL。

已验证的解析方式为：读取作品详情中的集标识，再请求 `/_dyn_plays/{作品ID}/{集标识}`，从 `video_plays` 的 `src_site` 和 `play_data` 提取来源及地址。按需支持已验证的页面形式，不执行页面脚本，不渲染上游 HTML，不安装站方播放器。

解析放在后端，前端只访问本站接口；不依赖第三方页面向本站开放跨域读取。首版不提供 Omofun 站内搜索和全站抓取，用户自行搜索后粘贴作品。

一次作品解析取得完整选集及逐集线路。集数较多时用异步任务显示进度，限制并发、请求数、响应大小和总耗时；不能让一个 HTTP 请求无限等待。

### 5.2 缓存结构与24小时规则

建议在现有数据库增加独立缓存表，形成逻辑独立的 Omofun 缓存区，无需新增数据库服务。以下是拟议字段：

| 数据 | 内容 |
| --- | --- |
| 缓存索引 | provider=omofun、字符串作品 ID、当前成功版本 |
| 成功快照 | 作品标题、稳定集标识、排序、线路来源标识及 HLS 地址 |
| 时间 | 最后完整解析成功时间、到期时间 |
| 刷新任务 | 状态、执行租约、开始时间、错误和有限重试信息 |
| 版本 | 单调递增的成功快照版本；旧版本保留或复制到房间播放快照 |

规则：

- 无成功缓存：启动解析，展示进度；成功后返回可选内容。
- 距最后成功解析不足24小时：直接返回已有快照。
- 达到24小时或用户主动重新解析：发起刷新；已有快照可继续用于展示，并明确刷新状态。
- 同一作品并发请求合并为一个刷新任务；主动刷新也受限频约束，不无限创建任务。
- 完整成功后原子替换当前缓存版本；失败或部分解析失败保留旧版本，记录错误，不延长其成功时间。
- 首次解析不完整时不标记完整成功，也不把部分结果伪装为完整选集。
- 24小时表示目录刷新周期，不保证 HLS 地址24小时有效。失效时提供重新解析及显式重新加载、换线操作。

Omofun 的来源标识不自动等于已配置采集站实例。同一来源可能贡献多个地址；同一集完全相同地址可以去重，但不同地址保留。不删除签名参数去重，不以返回数组下标作为长期线路 ID。优先利用稳定上游标识；无法可靠对应时产生新线路标识并保留旧房间快照。

## 6. 四种房间模式与播放快照

| 用户名称 | 内部类型 | 持久选择信息 |
| --- | --- | --- |
| 视频链接 | `external_url` | 当前外链及必要格式信息 |
| 本地视频 | `local_file` | 现有文件识别信息，不保存或广播本机路径 |
| 资源库 | `catalog` | 作品、剧集、线路/播放项 ID |
| Omofun | `omofun` | 作品 ID、稳定集标识、线路标识、所用缓存版本 |

模式、选择引用与当前播放描述分开。房间保存模式及选择；服务端在明确切源时生成房间播放快照，包含实际地址、格式、剧集、线路、数据版本及递增的 `source_revision`。

### 6.1 刷新不打断播放

缓存成功从版本 A 更新到 B 时：

1. 缓存默认指针指向 B，选集面板可以显示新剧集、新线路。
2. 正在播放 A 的房间继续使用自己的 A 播放快照，不广播切源，不替换 video.src，不暂停、不重置进度。
3. 新加入或重连的成员取得房间当前快照 A，不自行按作品 ID 解析成 B。
4. 有切源权限的成员明确选集、换线或重新加载后，房间才选择 B 的具体播放项并广播新的源版本。
5. 删除过期共享缓存不能让仍被使用的快照失效；房间持有必要播放描述，旧版本回收考虑引用生命周期。

“重新解析”只刷新候选数据，“重新加载当前线路”才改变房间播放源。即使刷新由该房间成员发起，也不把两项操作自动串联。当前线路在新快照中消失时保留正在播放的快照，下一次选择提示重新选线，不按下标替换。

该保证同样适用于资源库后台同步和普通元数据更新。管理员明确禁用、删除或下架的处理属于权限和可用性控制，应单独通知受影响房间停止使用，不能把普通刷新当作此类操作。

### 6.2 权限与同步

切模式、切集、切线和重新加载复用现有房间成员及主动同步权限；读取缓存不能赋予修改房间的权限。后台 CMS 操作仍仅管理员可用。

所有异步选片结果和播放事件检查房间源版本，用户已切模式时丢弃迟到结果。普通缓存更新不递增房间源版本；真正选择变化才原子递增并广播。

切集默认暂停并从头开始。跨线路时间轴尚未验证，不能因为集号相同就承诺无差别续播；首版手动换线，可明确选择尝试保留进度，但需允许人工校准。第一版不做每人独立换线或自动连播。

复用既有媒体引擎，播放描述显式携带 HLS 格式。上游解析成功与浏览器能否解码、加载分片分开验收；不增加任意视频代理。

服务重启后恢复持久模式与选择，暂停并重新建立播放描述，不承诺恢复重启前的连续播放或精确进度。当前进程内房间状态的部署限制继续保留。

## 7. 页面、接口与交互

现有管理员入口仍为“视频资源管理”，从页面进入资源采集站、资源导入和剧集详情；不恢复已移除的侧栏独立入口。

| 页面 | 后续变化 |
| --- | --- |
| 资源采集站 | 同步时间、最后成功时间、覆盖情况、启停及手动同步 |
| 资源导入 | 查询本地来源目录，保留名称/分类/更新日期和预览选择，已有作品可补集、补线 |
| 检索/同步任务详情 | 共通列表、进度、取消/重试；详情使用遮罩弹窗 |
| 视频资源管理 | 后续增加人工合并、拆分、锁定及映射修正 |
| 用户资源库 | 搜索已发布且未禁用的作品、查看选集 |
| 房间 | 四模式选择；资源库选片，Omofun 输入、刷新及选集选线 |

Omofun播放源面板提供链接/作品ID输入、当前状态和成功作品名、仅解析时显示的进度条、解析按钮和“打开选集”。输入链接提取的ID或直接输入的ID与房间成功解析作品一致时，按钮变为“重新解析”并强制重取（保留冷却限制）；不一致时显示“解析”，优先读24小时内成功缓存。不设置独立刷新按钮。房间以 `omofun_resolution` 保存解析对象和状态，独立于输入草稿及当前播放快照；即使未选择播放线路，重进也恢复解析作品。打开选集只打开当前成功结果，不触发解析，也不受输入框修改影响。弹窗使用共通卡片背景及暗色遮罩，打开后固定本次选集数据与播放源版本。点击线路应用到房间，界面不显示外链。底层映射至既有外链/HLS引擎，后端根据作品/集/线路ID及缓存版本取得地址，客户端不能以Omofun名义提交任意地址。线路名按上游前两位大写加“线路”，不再使用完整来源代码作为按钮文字。

界面继续使用共通组件、主题和中英文 i18n。反馈使用 toast，不在标题下长期占位；不增加开发提示和不必要副标题。选集使用数字按钮；线路优先缩写、否则名称，不额外显示 M3U8 后缀。失败仅显示必要原因和恢复入口。

新增接口按职责划分为来源目录查询/同步任务、用户目录、Omofun 解析任务/缓存读取、房间选择/播放快照；具体路径在相应阶段确定，避免将拟议地址写成现有 API。房间解析按内部标识操作，不能成为匿名通用网页抓取器。

## 8. 数据与请求边界

延续现有公网 HTTPS 请求防护、DNS 校验及绑定、超时、响应大小和限速策略；Omofun 使用固定允许域名并校验所有请求目标。任何新增重定向支持也须逐跳检查。上游内容按不可信数据解析，不执行脚本、不直接渲染 HTML。

缓存写入与房间切源分离，远程请求在数据库事务之外。控制 SQLite 写入批次和保留期限；不全量下载或探测视频。日志不输出完整签名地址、凭据或用户本地路径。

分类、采集站启停、人工覆盖、禁用与删除优先于自动同步。来源缺项、一次超时、播放失败均不直接触发批量删除。资源库发布状态与 Omofun 缓存状态是不同概念，互不代替。
